# 受治理 Run 的独立审核

`codex/v1.2.1` 为受治理 Agent Run 增加执行前身份快照、服务端完整文本输出清单和独立审核证据。业务 `complete` 必须同时满足已有子任务验收、组合验证和本次独立审核条件；操作者提交的 `proven`、文件数量或模型自报影响数量不能替代这些证据。

## 可证明的范围

`platform-closed-text-v1` 仅覆盖该次执行交付的文本输出集合。受治理执行器在调用模型前冻结 worker、node、session、preset revision、provider、model、任务目标和验收契约，并拒绝全部工具调用。服务端枚举结果中的全部文本块，为每块生成 SHA-256，再把任务/Run、摘要与全部条目编码成清单并计算整体摘要。调用方不能选择只登记其中部分文本。

该范围不证明仓库改动或连接器外部副作用。预设配置连接器、知识空间或保护提示引用时，身份快照标记为 `unknown`；执行结果可以保留，但 `complete` 返回 409。没有执行前快照的旧 Run、人类设备结果，以及无法归入纯文本的输出也不能验收。当前对所有闭合文本集合保守执行独立审核，数量小于 3 同样需要审核。

验收还检查同一任务的全部历史 Run：任何 `unknown` 快照都会阻止完成；已经执行、具有结果或产出但缺少有效闭合快照与服务端清单的历史，也不能被一次后来已批准的文本重跑消除。失败或取消结果携带文本同样不能绕过。纯分配后失败、没有执行痕迹、快照或任何产出的 Run 不阻断后续交付。历史 Run 已经具有闭合快照和完整文本清单时，可以由新一轮替代而无需对旧交付逐个重新批准；强制独立批准仍针对当前交付。

文本清单不覆盖上传附件。当前或历史任意 Run 存在任务附件时，整个任务均不能按文本范围验收，无论附件处于 pending、ready 还是 failed。已 prepare 的闭合 Run 拒绝追加附件；已经 `DONE`、`REJECTED` 或 `ARCHIVED` 的任务也拒绝通过旧 Run 追加附件，避免验收后扩大交付集合。本轮不提供人工标记已解决或绕过未知影响的入口。

## 正常使用链路

1. 当前生产 Run 执行前，数据面通过服务凭据调用 `PUT /v1/runtime/task-runs/{runID}/prepare`。请求只能声明实际 node/session/preset revision/provider/model，服务端从当前 Run、预设和存活心跳核对并冻结事实。客户端无权声明 profile 或 `proven`。
2. 数据面通过已有服务认证结果接口提交执行结果。结果与节点、会话和当前 Run 绑定，并保持不可修改；服务端在同一事务生成闭合输出清单。浏览器不能为已经 prepare 的 Run 首次提交结果。
3. 具有生产任务 contributor 权限的委派者调用 `POST /v1/tasks/{taskID}/runs/{runID}/review-tasks`，请求为 `{"reviewer_worker_id":"agent:reviewer-preset"}`，并附 `Idempotency-Key`。审核者必须是可用的另一个 Agent；接口复用生产任务项目与调度约束，在同一事务创建审核任务、审核 Run、精确清单绑定和调度 outbox。重复请求返回同一任务/Run，改变请求重用 key 返回 409。
4. 审核 Run 的 prepare 响应包含生产者冻结的目标、验收契约、完整输出清单、清单摘要和绑定有效期。执行器把这些内容作为不可信审核输入注入，审核者仍然不能调用工具。预设在创建后变更时，实际执行身份会重新校验，不合格身份不能借用旧绑定。
5. 审核者的执行结果必须恰好包含一个文本块，文本严格为 `{"verdict":"approve","manifest_digest":"确切摘要"}` 或 `reject`。Markdown、其他字段、不匹配摘要和其他值均不能作为批准证据。
6. 生产任务进入 `IN_REVIEW` 后才可完成验收。完成事务先拒绝任务历史中的未知影响和任意上传附件，再要求生产与审核 Run 都是各自任务当前最新的已完成 Run，审核绑定未超过 24 小时，审核身份满足异构规则，且不可变结果批准同一清单。审核任务正在重试或修改时返回 409，避免读取不稳定证据。成功审计包含生产 Run、审核 Run、清单摘要、scope、条目数与 `verified:true`。

审核 Run 达到执行态 `COMPLETED` 即可提供证据，无需先把审核任务的业务态设为 `DONE`。这避免审核的审核无限递归。业务验收操作者仍可与生产任务承接人相同，独立性由另一审核 Run 的执行快照证明。

已有独立创建、尚未 prepare 的审核 Run 仍可通过 `POST /v1/tasks/{taskID}/runs/{runID}/reviews` 绑定，body 为 `{"review_task_id":"...","review_run_id":"..."}`。正常页面应使用原子创建入口，防止先创建后绑定与数据面开跑竞争。审核任务不能成为生产任务的子任务，否则子任务业务验收会造成不必要的依赖循环。

## 存储与验证

迁移 `018_governance_run_reviews.sql` 与治理服务启动 DDL 创建相同的三张表：`governance_run_execution_snapshots`、`governance_run_output_manifests` 和 `governance_run_reviews`。快照、清单、结果和绑定均由服务写入，不存在浏览器提交审核批准的接口。

回归覆盖完整清单与摘要、执行前身份及任务契约冻结、结果伪造、审核缺失、拒绝/错误摘要/过期/旧 Run、历史未知影响不能被新批准替代、纯未执行失败可重跑、闭合旧文本可被替代、当前或历史附件拒绝验收、验收后附件写入、跨 realm、自审核、并发审核重试、原子创建回滚与幂等，以及迁移和启动 DDL 的数据库结构收敛。真实 PostgreSQL 证据与全仓验证结果由本轮交付记录汇总；未连接数据库的单元测试不能替代这些事务验证。
