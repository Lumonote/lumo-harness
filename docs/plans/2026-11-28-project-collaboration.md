# 项目实践与多工具、多 Bot 协作

目标：把项目规范、能力分工、隔离开发、测试与独立评审接入现有群组，保留原生引擎审批与可恢复会话。

## 实现

1. `project-practice-rules.ts` 从所选项目加载 AGENTS.md、CLAUDE.md、.lumo/project.md，生成有来源与摘要的统一快照；普通会话和群组共用加载器，项目流程固定快照。
2. `project-workflow-model.ts` / `project-workflow-planner.ts` 复用既有 DAG 校验，按明确能力、可用性、工作负载分配 Bot。独立评审成员不承担实现任务。默认草稿只有一项任务；AI 拆解通过协调成员真实调用并验证结构化建议。
3. `project-worktrees.ts` 在 Git 管理目录下创建独立工作树及 codex/lumo-* 分支。依赖任务获得前序提交，互不依赖任务有界并行；冲突保留现场。原始 checkout 只在显式合并时做快进，并检查原始分支、提交和未提交改动。
4. `project-workflow-runner.ts` 复用 EngineHost/runRoleTurn，采集实际代码差异和提交；`project-workflow-checks.ts` 执行用户列出的 argv 命令，记录退出码、输出、时间和所验提交。独立评审通过后标为可合并，文本中的“测试通过”不能代替命令证据。
5. 群组右栏和 `/workflow` 提供可编辑计划、状态与证据；任务会话加入群组归属、审批过滤及事件订阅。重启中断的流程不会自动重发或自动合并，历史和工作树保留。

## 验证

- 规则内容变化、越界路径、超限和来源边界。
- 能力路由、不可用引擎、独立评审、无环依赖、规划输出中的非法执行配置。
- 真实 Git worktree、并行分支、依赖集成、冲突、源 checkout 变化、证据与提交绑定。
- 实际子进程成功/失败/超时/取消/输出上限以及子进程回收。
- 群组 API + 临时仓库的完整流程（模型传输替身明确标记），存储恢复、会话归属与原生审批。
- 前端表单、命令入口、未保存草稿、验收条件与合并入口。

本机流程证据不冒充控制面治理验收。模型服务认证和真实远端执行继续按实际环境记录。
