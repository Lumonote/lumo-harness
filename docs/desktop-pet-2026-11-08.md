# 鲸鱼桌面伙伴开发记录

鲸鱼悬浮窗复用对话首页的官方鲸鱼跃海素材，与 Tauri 主窗口并行运行在操作系统桌面上。
它支持选择工作空间、附带文件直接发送消息，也提供回到工作台和轻量互动的入口。
业务执行使用现有会话与任务服务。

## 原生窗口

- 独立无边框透明窗口，无主窗口父子关系，主窗口最小化不会隐藏桌宠。
- 默认置顶，可拖动；折叠与展开保持右下角锚点，窗口按显示器缩放与工作区边界定位。
- 菜单栏／系统托盘提供显示、隐藏入口。隐藏可恢复，关闭应用会退出全部窗口及 runtime。
- `desktop-pet.json` 只保存置顶、随应用启动显示以及位置。随应用启动显示不是操作系统开机启动。
- macOS 透明窗口使用 Tauri 的 `macos-private-api` 支持，桌面安装包沿用现有直接分发方式。

### 2026-11-09 展开面板尺寸修复

展开窗口从 `380×560` 调整为 `360×500` 逻辑像素。标题改为单行，减少输入框、留白和展开态鲸鱼高度；
卡片只让中间内容滚动，收起按钮、快捷入口和底栏保持可见，空反馈不预留空间。
较矮工作区会减少鲸鱼预留高度，继续沿用原生显示器边界约束。

浏览器复现原布局时，卡片可视高度 348px、内容高度 433px，底栏超出卡片；
修改后的 `360×500` 预览中，两者均为 331px，中间内容为 198px，底栏完整显示。
该预览使用真实 HTML/CSS 与未连接 native bridge 的外观模式，不代表已替换用户安装的应用；
更小视口的浏览器复验因自动审批并发错误未执行。相关桌宠与打包回归 5 文件、76 项通过，
Rust 格式检查通过。

## 动作与表情

收起时只显示鲸鱼跃海动画，不显示身份、待命状态或动作按钮文字。动效消费上游
`@deepseek-ai/dsh-client-ui-brand-official` 的原始 `breach-atlas.webp`：137 帧、5.7 秒、
192×108 点阵与 16:9 比例，造型和动作数据不重绘、不重采样。素材副本的 SHA-256 与上游
相同，来源和许可记录在 `platform/desktop-assets/pet-artwork.NOTICE`。

桌面使用固定实蓝 `#405ce8`，去掉背景装饰用的透明衰减；按桌面用途提高点阵覆盖率，
半径为原值的 1.6 倍并限制在网格的 0.64 倍，不透明度为 `min(1, sqrt(alpha) × 1.6)`。
原图集、点位置及动作轨迹保持一致，身体轮廓更实，水花保留轻重层次；没有模糊滤镜或残帧叠加。
它定时自主播放，也可点击重播。静止时保留同一素材的真实帧；减少动态效果时显示静帧。
隐藏窗口及交互忙碌时停止帧工作，退出释放图集像素、定时器和观察器。

## 工作空间、发送与附件

桌宠通过 `pet_workspaces` 获取现有工作空间列表及当前选择，使用真实非空工作空间 ID。
用户可以切换或刷新列表；工作空间未加载、为空或已移除时禁止发送，不会默默改投其他空间。
列表名称作为文本渲染。输入框接受最多 12,000 个字符，支持 ⌘ / Ctrl + Enter 发送。

`pet_open_workbench` 区分导航与提交：空消息且无附件的 `chat` 打开新对话；`home` 和
`tasks` 只执行各自导航，不携带工作空间参数。有文本或附件的 `chat` 请求包含
`workspaceId`、`requestId` 和 `attachments`，原生壳不唤起主窗口、不收起桌宠。
客户端通过公开 Workspace／Session 服务创建并保留独立会话，上传文件后调用
`beginSubmission` 与 `prompt(..., 'queue', ...)`，消息进入该会话的正常执行链。

附件最多 4 个，单个不超过 8 MiB，总计不超过 16 MiB。这是桌宠 IPC 的传输上限，
不是对上游完整附件服务能力的重新定义。选中的浏览器 File 暂存于桌宠内存，可逐项移除；
发送时读取真实字节，以 `{name, mimeType, base64}` 传递，base64 不含 data URL 前缀。
客户端将 PNG／JPEG／WebP／GIF 交给公开 `uploadImage`，其他文件走公开 `upload`，
使用上传收据构造消息附件。原生壳和客户端再次校验数量、编码及字节大小。

发送期间禁用输入、附件修改与工作空间切换，防止回执清掉后来编辑的内容。桌宠只有收到
包含非空 `sessionId` 的提交成功回执才清空文字与附件，继续保持展开；失败保留内容。
未确认结果不会显示为已发送，附件读取过程中关闭桌宠会停止编码，不再后台发出该请求。

同一内容、附件与工作空间的失败重试保留 `requestId`，任一内容变化后使用新 ID。
客户端保留已创建会话及已成功上传的收据，提交前的可重试失败不重复创建会话或上传已完成文件。
桥接入口保持同步入队，后台使用 SHA-256 校验同 ID 的请求内容；重复请求在核对后复用
原结果，不允许同一 ID 换消息。结果账本只保留摘要、状态、会话 ID 及上传收据，
不在终态条目中长期保留附件 base64。
Host 通过独立 SQLite KV 单元持久保存该账本，以本机持久 BrowserAuth grant 的隔离摘要
绑定真实本机 owner；浏览器提交的 owner 只标识窗口租约，不作为账号身份。参与进程
取得同一个文件锁后重新读取、比较 revision 再写入。开始创建会话和提交消息前分别
持久写入 creating／submitting 围栏，WebView 重载或 Host 重启也不会把未知结果当成新请求。
同 owner 最多保留 10,000 项；终态去重记录不自动淘汰，容量满时拒绝新发送。
Host 已进入提交阶段时，原生超时只查询同一请求，不取消或重新发起可能已经受理的消息；
回执不确定时显示“发送回执未确认，请在对应对话中核对”，不会把不确定状态当成可重新发送。
成功回执仅证明 Host 已受理消息，不代表真实模型已返回或任务已经完成。

准备阶段的 claim 暂时失败可以重试；上传收据持久化结果未知时，重试先重新 claim 权威
revision 和附件记录，再决定是否继续上传。已创建会话保持不变。持久提交围栏失败且尚未
调用 Host prompt 时，移除乐观待发送项；该请求仍保持结果待核对，不自动再次提交。

查看任务打开本机会话任务面板，实时订阅本地会话状态，支持搜索、只看运行中以及继续对话，
不调用集群治理或调度 API。打开工作台与新建对话使用现有桌面主窗口。

## 资源与权限

`lumo-pet://localhost/pet.html` 使用内嵌资源，在开发和发行模式都不依赖 runtime 的 HTTP 页面。
Windows WebView2 使用相应的 `http://lumo-pet.localhost` 自定义协议地址。
桌宠命令同时验证窗口标签与精确页面地址，并限制桌宠导航；工作台不需要新增远程 IPC 权限。
草稿与附件不写入查询参数、日志或桌宠设置。桌宠进程中的待发送文件仅保存在内存；
发送成功、删除附件或关闭窗口时释放相应引用。
主窗口保持在已握手的本地运行时 origin；普通外链在系统浏览器打开。官方账号登录使用的
预开空白窗口保留真实 WindowProxy，授权地址就绪后交给系统浏览器，辅助窗不安装桌宠桥。

## 原生弹层定位兼容

工作台客户端通过平台插件安装 CSS anchor 兼容层。它先做真实几何探测；原生能力完整时，
仅接管实际停留在左上角、且明显偏离触发按钮的锚定弹层。正常原生菜单与没有锚点的设置
Modal 保持组件自己的定位。菜单随滚动、窗口大小与可视区变化更新，尺寸仍遵守组件自身
限制；组件在菜单打开时更新的内联尺寸会保留，卸载恢复其最新值。

当前上游真实 ModelSelect、Menu、子菜单、Modal 和 SettingsRoot 已在隔离 Chrome 中验证；
ModelSelect 也在 Tauri WKWebView 中验证了按钮上方 8px、右侧对齐；完整 SettingsRoot 在
1440×888 原生窗口内为 800×800，位置 `(320, 44)`，居中正常。故障注入移除触发按钮
的锚点后，真实 ModelSelect 从 `(12, 12)` 恢复到按钮旁，其材质 backing 同步跟随。
当前源组件没有复现用户现场的全部左上角错位，现场根因仍需对应运行版本的 DOM 与样式
证据；这些验收不能解释成已证明某个特定浏览器版本不支持 CSS anchor。
